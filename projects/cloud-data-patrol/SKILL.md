# 雲端自動化巡邏機制 (INBOX/OUTBOX)

本技能用於協助使用者全自動或手動檢視指定的 `E:\我的雲端硬碟\INBOX_待處理` 資料夾，並將新發現的資料進行後續處理（如詢問文件生成需求、圖片排版等），最後將資料歸檔以避免重複作業。

## ⚙️ 核心流程與規則

1. **觸發檢視**：
   - **自動排程**：預設每日 08:00 到 18:00 間每 4 小時（08:00, 12:00, 16:00）自動執行一次，18:00 之後暫停自動巡邏，以手動觸發為主。
   - **手動觸發**：使用者隨時可透過對話下達檢查指令（如「幫我巡邏 INBOX」）。

2. **新資料偵測與詢問**：
   - 掃描 `INBOX` 資料夾內的未處理檔案。
   - 如果發現**新檔案**，必須主動中斷流程並詢問使用者：
     > 「目前 INBOX 內有新資料，請問要製作成什麼樣的文件？」
   - 等待使用者回覆後，依據需求進行後續產出。

3. **照片與文件處理邏輯**：
   - 若 `INBOX` 內包含**照片/圖片檔**與**錄音檔**，且使用者的需求為產出「會議紀錄」或 Word 檔：
     - 自動呼叫 `meeting-record-generator` 相關流程或腳本 (`export_to_word.py`)。
     - 自動聽取錄音檔萃取會議重點，並挑選最合適的照片（如大合照）。
     - 將照片嵌入至 Word 文件中，自動調整圖片大小（置中、寬度預設 15cm）。
     - 產出的完成品需統一存放到您的指定目錄：`E:\我的雲端硬碟\OUTBOX_已處理\`。

4. **資料歸檔與防重複機制**：
   - 每當一批檔案被「用於生成文件」或「已經詢問過使用者」後，必須將它們移出 `INBOX` 根目錄。
   - 在 `INBOX` 內動態建立一個**封存子資料夾**（系統自動命名，推薦格式：`Processed_YYYYMMDD_HHMM` 或 `Archive_已處理`）。
   - 將剛才處理過的檔案全數搬移至該子資料夾，確保下次巡邏時不會再掃描到相同的檔案。

## 🚀 執行排程指令指南 (Agent 內部參考)
當使用者要求啟動此巡邏機制時，AI Agent 需呼叫 `schedule` tool 設定 cron job：
- `CronExpression`: `0 8,12,16 * * *` (每日 08:00, 12:00, 16:00 執行)
- `Prompt`: `[cloud-data-patrol] 執行 INBOX 巡邏，檢查是否有新檔案。如果有，請依照技能指示詢問使用者並歸檔。`
- `IsDaemon`: `true`
