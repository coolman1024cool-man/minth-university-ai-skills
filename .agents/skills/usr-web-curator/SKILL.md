## 🛡️ 成果品質篩選嚴格準則 (Quality Control Rules)

為維護官方展示平台之最高專業度與公信力，**必須嚴格執行以下過濾標準**：

1. **排除紙本行政文件照片**：
   - 🚫 **絕對剔除**：直式 A4 白底黑字之紙本簽到簿、出席簽到名冊手寫拍照、活動議程單張、講義翻拍、題庫考卷、器材採購請購單。
   - 💡 **演算法判斷**：長寬比符合直式 A4、平均亮度高（大片白紙）且色彩飽和度低者，自動排除。

2. **排除非核心採購與耗材包裝**：
   - 🚫 **絕對剔除**：單純拍攝廠商外送食材瓦楞紙箱、調味料塑膠瓶罐外盒、純粹靜態器材零件特寫。
   - 💡 **核心原則**：非本計畫核心產出，不得進入專案資料夾。

3. **落實「人本實作紀實」**：
   - ✅ **必須保留**：包含「2 人以上師生操作、專家講座、社區居民共學互動、大合照、實體產出展示」之高清晰紀實照片。
   - 📌 **數量上限**：單一活動照片收錄**嚴格限制在 20 張以內**，擇優篩選最具代表性與動態感之視角。

## 🎬 多媒體影音輕量化串流標準 (Video Transcoding SOP)

原始錄影或剪輯檔動輒 300MB～1GB 以上，直接上傳會導致網頁嚴重卡頓。必須透過 `ffmpeg` 執行串流轉碼：

- **轉碼指令規範**：
  ```bash
  ffmpeg -y -i "原始影片.mp4" -vf "scale=-2:720" -c:v libx264 -crf 28 -preset fast -c:a aac -b:a 96k "public/assets/video/輸出檔名.mp4"
  ```
- **產出標準**：
  - 解析度：720p（1280x720 或自動維持原比例）。
  - 視訊編碼：H.264 (libx264)，CRF 28。
  - 音訊編碼：AAC，位元率 96 kbps。
  - 體積目標：壓縮至 15 MB ～ 45 MB 之間，兼顧清晰畫質與秒開流暢度。

- **前端「方案 A 播放清單切換器」實作規範**：
  - 在彈跳視窗（Modal）中配置單一主播放器 `<video id="player_xxx">`。
  - 影片下方配置切換播放清單按鈕群 `<button onclick="switchVideo(...)">`。
  - 當使用者點選不同影片標題時，即時切換播放源，無需開啟多個視窗。

每當完成資料分類或網頁功能更新後，依序執行：
1. **HTML 語法檢驗**：確認無未閉合標籤或 DOM 結構損壞。
2. **Firebase 熱部署**：
   ```cmd

   firebase.cmd deploy --only hosting
   ```
3. **Git 版本控制提交與推送**：
   ```cmd
   git add public/index.html public/assets/
   git commit -m "feat(web-curator): 更新成果資料庫與策展內容"
   git push origin master
   ```
4. **成果沉澱**：將當日新增或調整之活動紀錄、照片數量與線上網址寫入 `Obsidian_Vault/YYYY-MM-DD.md`。
